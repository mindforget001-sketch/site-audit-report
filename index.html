02

资源重量解剖

首页实测下载字节（gzip 后）。最刺眼的问题不是产品图，而是三张 PNG 格式的公司 Logo —— 合计 177KB，其中 59KB 那张还被 <link rel="preload"> 当成关键资源优先加载，直接抢占首屏大图的带宽。

Logo（应转 SVG） 首屏 / 产品图 脚本
−170KB

把三张 PNG Logo 换成 SVG（约 4KB），并移除对 Logo 的 preload、改为 preload 首屏 hero 图。这是全站投入产出比最高的一处改动：半天工作量，首屏关键资源减重约 170KB，LCP 直接受益。产品图压缩走 squoosh.app，转 AVIF/WebP 质量 72 并配 srcset。

04

整改路线图

按"先止血、再补基建、后做增长"排序。P0 是不做就等于白建站的项，合计约 4 人日即可让站点从"摆设"变成"能收询盘"。

P0 止血

≈ 4 人日
  • 43 个产品页内嵌 RFQ 询盘表单，型号自动预填
  • 表单换插件 + Turnstile 反垃圾 + 图纸附件上传 + 自动回执
  • 验证并配置 SPF / DKIM / DMARC，否则回盘进垃圾箱
  • Logo 转 SVG，移除 Logo 的 preload
  • 删除主题硬编码的 robots 标签，消除冲突
  • 撤下无法验真的 IATF 声明，或补证书扫描件

P1 基建

≈ 5 人日
  • 上 CDN + 页面缓存，把 TTFB 压到 0.8s 以内
  • 关闭 WooCommerce 购物车，全站改询盘制
  • dequeue 无关电商 JS，移除 jquery-migrate
  • Google Fonts 改自托管 woff2 子集
  • 社交链接：建真实主页或整块删除裸域名链接
  • 统一厂址与工商主体名，补营业执照
  • canonical 补尾斜杠、og:type 改 website、合并双 sitemap
  • nginx 补安全响应头，关闭 xmlrpc

P2 增长

持续投入
  • 建 /blog/，30 篇选型/标准长尾内容起步
  • 每 SKU 补 6–8 张证据图：尺寸图、盐雾、包装、装机
  • 做 PDF Catalogue，留邮箱换取（线索捕获）
  • 产品线收敛：主站聚焦喉箍，机加工/冲压拆出去
  • 要么真做中文站，要么彻底删掉 /zh/ 空壳路径
  • 域名续费 5–10 年，去掉短注册期信号
05

可直接套用的补丁

以下五段针对已实测确认的具体缺陷，可直接交给建站方执行。

本次未能验证的一项

邮件认证记录（SPF / DKIM / DMARC / MX）无法核实：本机对 dns.google 与 cloudflare-dns.com 的 DoH 查询均返回 http=000（网络不可达），因此不能断言其缺失。但域名 2026-11-04 才注册、仅 8 天，新域名未配邮件认证的概率很高，而这直接决定询盘回盘是否进垃圾箱。请在本地执行以下三条命令确认：

nslookup -type=TXT jinnuoparts.com
nslookup -type=TXT _dmarc.jinnuoparts.com
nslookup -type=MX  jinnuoparts.com
检验方法：curl 抓取原始 HTML / 响应头 / 资源字节，Verisign RDAP 取域名注册记录，站点 sitemap.xml 取 URL 全量，DoH 查 DNS（未通）。
